# Local collision cooking — issue 2

The converter now has opt-in local box, convex hull and VHACD decomposition
using the in-process Apache-2.0 Parry library. No Studio or server cooking is
invoked. The command accepts `--collision-config recipe.json`; all decomposition
settings are required JSON data, including the hull budget and voxel resolution.
The minimum resolution of two is an algorithm bound (the voxelizer divides by
resolution minus one), not a performance policy. Box/hull do not need tuning.

The first payload writer emits documented CSGPHS v5 records. The implementation
reference is [rbx_mesh union_physics](https://github.com/krakow10/rbx_mesh/tree/master/src/union_physics),
whose v3/v5 records contain a fixed preamble, scalar-counted f32 positions and
u32 triangle indices. Tests decode generated bytes using an independent reader.
Tests also distinguish box from hull, compare repeated decomposition output,
exercise disconnected geometry and verify non-default hull budgets.
The exact-hull reconstruction can exceed VHACD's split budget. The converter
checks the final count and fails explicitly if it exceeds the requested budget;
it does not silently merge hulls, drop pieces or increase the configured limit.

## Acceptance is not yet complete

The installed Studio executable contains strings for v8 collision migration,
Zstd compression, voxel decomposition and HACD. Those are evidence of engine
implementation paths, NOT proof that our v5 payload can be assigned to a current
MeshPart or deployed. The current payload is a format-conformance milestone.
Each manifest records `engineVerified: false`; issue 2 remains open until current
native consumption, physical behavior and necessary mass/inertia handling are
established. v8 encoding may be required; do not paper over that with a cloud cook.

The CLI emits `.physics` sidecars with hashes and hull counts. This does not yet
wire them into native place instances. Scene assembly and collision property
binding belong to the corresponding place/model work.
